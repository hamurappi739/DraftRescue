# DraftRescue — UI/UX proposal для понятного Apple-подобного интерфейса

Статус: дизайн handoff, реализацию не включает.

Цель: человек запускает DraftRescue и за несколько секунд понимает три вещи:

1. это приложение возвращает несохранённый текст после неожиданного закрытия окна;
2. оно работает локально и не является историей всего набранного;
3. если восстановление безопасно, есть одна понятная кнопка `Восстановить`.

Документ уточняет существующие `UI_UX_MASTER_SPEC.md`, `FIRST_RUN_UX_SPEC.md`, `UI_COMPONENT_STATE_SPEC.md` и `UI_COPY_BASELINE.md`. Он не меняет privacy, recovery matching или фазовые границы.

## 1. Визуальное направление: Apple-подобное, не «стиль ИИ»

Под Apple здесь понимаются принципы ясности, иерархии и спокойствия, а не копирование iOS/macOS.

- Много свободного пространства и короткие группы информации.
- Один акцентный цвет для главного действия; без градиентов, стекла, неона и декоративных иллюстраций.
- Нейтральный фон, мягкая карточка, тонкая граница, очень умеренный радиус 10–12 px.
- Системный шрифт Avalonia/Windows; не подключать декоративный шрифт ради внешнего эффекта.
- Три рабочих размера текста: заголовок 26 px, секция/карточка 16 px, обычный текст 14 px; служебный текст 12–13 px.
- Длинные тексты не растягивать на всю ширину окна; держать читаемую колонку.
- Анимация только функциональная и короткая. Никаких пульсирующих индикаторов записи, «успешных» салютов или активности на каждый символ.
- Светлая и тёмная тема — через theme resources, а не через зашитые RGB-значения.

Итоговое ощущение: маленькая системная утилита, которой доверяешь, а не аналитическая панель и не AI-продукт.

## 2. Главный пользовательский сценарий

```text
Первый запуск
  → коротко объяснить пользу и границы
  → Continue
  → Recovery: «Пока нечего восстанавливать»

Обычная работа
  → окно скрыто, нет уведомлений о каждом изменении

После потери текста
  → редкое уведомление «Доступен черновик» (без текста)
  → Recovery
  → Preview / Copy / Restore / Discard
```

Окно управления не должно притворяться редактором, журналом или монитором печати.

## 3. Первый запуск: объяснить за один экран

Заголовок:

> DraftRescue возвращает несохранённый текст

Подзаголовок:

> Если поддерживаемое окно закрылось неожиданно, безопасный черновик можно будет открыть и восстановить.

Четыре коротких пункта с одинаковой визуальной иерархией:

- Черновики остаются на этом компьютере.
- Пароли и защищённые поля никогда не сохраняются.
- Приватный режим браузера по умолчанию исключён.
- Черновики автоматически истекают.

Нижняя строка:

> DraftRescue не ведёт историю набора и не отправляет текст на сервер.

Главная кнопка: `Продолжить`.

Не показывать fake demo draft, регистрацию, вход в аккаунт, «разрешите всё» и технические термины UI Automation/DPAPI.

## 4. Recovery — экран по умолчанию

### Верхняя область

Слева:

- `DraftRescue`
- `Вернуть несохранённый текст`

Справа:

- обычная кнопка `Настройки` с текстовой подписью;
- при узком окне допускается иконка, но у неё обязательно доступное имя.

Не показывать counters, CPU, количество наблюдений, process ID, fingerprint или внутреннюю confidence percentage.

### Пустое состояние

Центральная композиция без большой иллюстрации:

> Пока нечего восстанавливать

> Если поддерживаемый черновик появится после неожиданного закрытия окна, он будет показан здесь.

Небольшая спокойная подпись:

> Локально на этом компьютере · черновики истекают автоматически

Это должно сразу объяснять назначение и одновременно не создавать ощущение, что приложение записывает всё подряд.

### Карточка черновика

Порядок информации:

1. безопасное имя приложения/контекста;
2. грубая метка поля, только если она разрешена политикой;
3. `Обновлено ...` и `Истекает ...`;
4. действия.

Карточка не расшифровывает и не показывает snippet автоматически. Полный текст появляется только после явного `Предпросмотр`.

Кнопки:

- `Восстановить` — акцентная, только если Application сообщает, что попытка сейчас допустима;
- `Предпросмотр` — вторичная;
- `Копировать` — вторичная, явное действие с clipboard;
- `Удалить` — в меню/терциарная destructive action.

Если поле нельзя безопасно сопоставить:

> Не удалось безопасно сопоставить исходное поле.
>
> Можно посмотреть или скопировать этот черновик.

Кнопки `Восстановить всё равно` не должно быть.

## 5. Preview и результат действия

`Предпросмотр` открывает простой read-only dialog/detail pane:

- заголовок `Предпросмотр черновика`;
- источник и время обновления;
- выделяемый, но не редактируемый текст;
- `Копировать`, `Восстановить`, `Удалить`, `Закрыть`.

Открытие Preview ничего не вставляет и не меняет в исходном поле. Закрытие возвращает фокус на карточку.

После Restore показывать маленькую inline-подпись:

> Черновик восстановлен.

При `AppliedButUnverified` не удалять последнюю копию и показать:

> Текст вставлен, но результат не удалось проверить. Копия восстановления сохранена.

При любом unsafe/ambiguous результате оставить `Предпросмотр` и `Копировать`, не предлагать обход безопасности.

## 6. Settings — только решения, которые понятны человеку

Экран состоит из трёх компактных групп:

### Срок хранения

> Как долго черновики могут оставаться на этом компьютере.

Выбор: `5 минут`, `30 минут`, `1 час`, `6 часов`, `24 часа`, `Другое`.

Не предлагать `Навсегда`.

### Запуск

`Запускать DraftRescue при входе в Windows` — простой переключатель с коротким пояснением.

### Приватность

Read-only строки, не переключатели:

- `Приватный режим браузера — Не сохраняется по умолчанию`
- `Пароли и защищённые поля — Никогда не сохраняются`
- `Облачная обработка текста — Не используется`

Нижняя destructive action: `Удалить все доступные черновики` → подтверждение `Это действие нельзя отменить.`

## 7. Поведение окна и фона

- После явного запуска открыть Recovery.
- При запуске вместе с Windows работать в фоне и не красть фокус.
- Закрытие окна скрывает его, но не останавливает защиту.
- `Выйти из DraftRescue` — отдельная команда с честным предупреждением, что новые черновики не будут защищены.
- Tray-меню минимально: `Открыть DraftRescue`, `Настройки`, `Выйти`.
- В tray никогда не показывать snippets, список текста, counters или «последние символы».

## 8. Правила ясности и доступности

- На экране не более одного визуально главного действия в каждой области.
- Кнопки подписаны словами; иконки не заменяют смысл там, где действие может быть непонятно.
- Клавиатурная навигация и видимый focus ring обязательны.
- Состояние нельзя передавать только цветом.
- В destructive confirmation фокус по умолчанию на `Отмена`.
- При масштабировании Windows 125–200% текст и действия должны переноситься без горизонтального скролла.
- Ошибки говорят человеческим языком: `DraftRescue не смог получить доступ к этому полю.` Без COM-кодов и сырых exception message.

## 9. Что сейчас не так в shell

Текущий `MainWindow.axaml` — технический Phase-0 экран с текстом `Privacy-first skeleton` и перечислением отсутствующих функций. Он полезен как инженерный smoke screen, но не подходит для реального пользователя: не объясняет пользу через сценарий восстановления и не даёт Recovery/Settings IA.

Следующий UI implementation package должен заменить этот shell на состояния `FirstRun`, `RecoveryEmpty`, `RecoveryReady`, `Preview`, `Settings` и safety-aware actions, но только после авторизации соответствующей фазы. Не добавлять UI-обходы в текущий Phase-1 observation work.

В текущем shell уже разрешены только презентационные настройки: русский/English и Light/Dark. Их реализация не меняет recovery safety, не читает текст и не добавляет persistence.

## 10. Критерий готовности дизайна

Дизайн считается понятным, если новый пользователь без документации может ответить:

- «Что делает приложение?» — возвращает несохранённый текст;
- «Где мои данные?» — локально, с автоматическим сроком истечения;
- «Что нажимать?» — `Восстановить`, если безопасно, иначе `Предпросмотр` или `Копировать`;
- «Записывается ли вся история?» — нет.

До реализации UI остаются отдельные инженерные решения: application-level presentation states, безопасное получение metadata-only card labels, storage/recovery use cases и tray/startup integration. Ни одно из них не разрешает чтение контента в текущем Phase 1.
